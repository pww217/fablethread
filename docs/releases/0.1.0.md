# Release 0.1.0

Released: 2026-04-30

## 📋 Summary

Release with 6 commit(s).

## 🔧 Engine Changes

- ccya: delta facts, chronicle-canonical narrative, named NPCs
- Initial commit: ccya MVP — local LLM-backed text adventure with two-call turn pipeline

## 🎨 UI Changes

- Reliable turn flow v4: extract slim, NPC hydration, narrate/extract thinking flags, diff toast UX - Extract: replace embedded Pydantic JSON Schema dump in extract_system.j2 with a concise TS-style schema (~few hundred tokens vs ~2000-3000); Ollama format= grammar, when on, still does the constraint work. - Extract: 2 new worked examples (new-quest creation + inventory swap) target the highest failure modes (quests, inventory). Total 5 examples, each wrapped in {% if enable_thinking %}. - Thinking: split into two independent flags. enable_extract_thinking (default false) gates the <thinking> block before extract JSON. enable_narrate_thinking (default false) gates an optional planning block before narration; joined narrate output is run through _strip_thinking before chronicle, extract, and TurnResult.narrative. - NPC hydration: NpcRef.name/title/bio are optional. apply_delta hydrates missing fields from state.compendium.npcs[id] when the model emits {id, notes} only — saves ~150-250 output tokens/turn on returning NPCs. extract_user.j2 drops the redundant bio repeat from Present NPCs. - UI: diff toast 10s with Esc / x dismiss; vertical bordered panel above action pills; lines render inline markdown so *italic* / **bold** in item/NPC names display. Header tagline (gold) renders inline markdown and updates document.title each turn. Removed redundant Title: line (already in header). - Streaming markdown: render at narrate_done phase so formatted prose appears during the extract wait. - Progress timer: resets to 0.0s at extract_start so "Processing outcome..." doesn't continue counting from narrate. - Bug fix: tooltip portal needed top:0; left:0; width:0; height:0 on the position:fixed container so absolute child coordinates are viewport-relative. Tests: 76 passing. Observed input ~6600 -> ~4500, output ~5200 -> ~4500, total turn ~80s -> ~21-37s on local 26B.
- ccya: two-sidebar UI, quest failure states, fact supersession, Ollama tuning UI / layout - Split state panels into a two-sidebar layout. Left sidebar holds   Player, Scene, Location, Quests (in that order). Right sidebar holds   Established Facts, Inventory, and a single combined Debug card. - Replaced "Concept" label with a left-aligned, full-width concept block   inside the Player card; fixed wrapping/alignment via .stat-concept CSS. - Inventory panel scroll height bumped 440px -> 660px; individual items   use tighter padding (3px) and smaller fonts (11/10px). - Established Facts panel scroll height bumped 220px -> 308px and now   shows all 25 facts (scrollable), no truncation in UI. - New /panels/state-left and /panels/state-right routes; turn_complete   swaps both. Legacy /panels/state still works for compatibility. Debug panel redesign - Removed standalone errors card; merged into one Debug card. - Errors block surfaces trace IDs with a "Clear errors" button posting   to /panels/debug/clear-errors. - Recent Turns table: last 10 turns with trace, first-token time,   narrate total, extract total, retries, tokens in/out; rejection rows   highlighted. Backed by new _recent_turn_metrics() helper that parses   events.jsonl. - Concise status block: model, num_ctx, mock mode, schema enforcement,   log file path with tail -f hint. Verbose raw I/O still goes to   logs/llm-g.log only. Quest failure states - QuestObjective gains failed: bool. quest_updates accepts status   "failed" in addition to "completed"/"abandoned"/"active". - apply_delta side-effects: status="completed" marks all objectives   done; status="failed" marks all unfinished objectives failed;   status="abandoned" leaves objectives untouched. - Single objectives can be marked failed via {description, failed: true}. - extract_system.j2 + a worked example document the new semantics. Established facts management - established_facts_max raised to 25; engine caps oldest-first. - New StateDelta.established_facts_remove with normalized string match   (whitespace/case/trailing-punctuation tolerant) so the LLM can   supersede stale facts (e.g. "ship damaged" -> "ship repaired") rather   than accumulating contradictions. - extract_user.j2 now lists current facts so the model has exact   strings to copy into established_facts_remove. Ollama tuning (Apple Silicon) - New scripts/ollama-launch.sh exporting OLLAMA_FLASH_ATTENTION=1,   OLLAMA_KV_CACHE_TYPE=q8_0, OLLAMA_NUM_PARALLEL=1,   OLLAMA_MAX_LOADED_MODELS=1, OLLAMA_KEEP_ALIVE=10m, OLLAMA_MLX=1. - Makefile targets: make ollama-launch (run script) and make ollama-env   (print launchctl setenv lines for GUI users). - README section documents env var rationale, GUI vs CLI setup paths,   and how this interacts with num_ctx / extract_num_ctx model reloads. Server / CLI - Startup runs ollama warmup via asyncio.create_task so the web server   binds and serves the UI immediately; warmup completes in background. - /healthz now reports ollama_version from /api/version. - CLI startup banner prints the server URL as an OSC 8 hyperlink in   TTYs, falls back to plain URL elsewhere. Tests + lint - Smoke tests cover normalized fact removal, 25-fact cap, quest status   side-effects (completed/failed/abandoned), single-objective failure,   and that extract messages include established_facts. - Cleaned up imports in engine.py (E402) and removed unused import in   test_engine_smoke.py (F401).
- Add ccya — LLM-powered choose-your-own-adventure game (Expanse setting) Full implementation of a local-LLM text adventure engine backed by Ollama, built on FastAPI + HTMX + Alpine.js + Tailwind. Started from a local agent scaffold and heavily remediated, extended, and polished. Engine & backend - Two-call pipeline: streaming narrate (call 1) + structured JSON extract (call 2) - Pydantic schema validation with single auto-retry and error feedback - StateDelta now includes scene_tags, present_npcs (NpcRef), enabling scene   state to persist and update each turn - Quest create-or-update semantics fixed (validator was blocking new quests) - apply_delta: auto-clears present_npcs on location change, persists scene_tags - extract_num_ctx matches num_ctx to prevent Ollama model reload between calls - enforce_extract_schema flag (default off) — freeform JSON parse avoids   grammar-constrained generation penalty - log_llm_io flag — full prompt/response payloads logged at DEBUG level - established_facts_max bumped to 25 Prompts - Extract prompt: explicit quest resolution instructions (check every active   quest, mark objectives done, set status completed/abandoned) - Extract prompt: present_npcs and scene_tags field guidance added - Narrate prompt: instructs LLM to make quest resolution explicit in prose - Opening scene revised to Expanse universe (Ceres, Belter smugglers, the Wretch) - Belter slang glossary removed from opening scene Setting pack: expanse-belter - Captain Niko Sato aboard the Wretch, Ceres Station Lower Levels Market - Crew: Davi Moreau-Ng (pilot, ex-MCRN) and Sigge Petrescu (enforcer) - Seed state includes ~25 established facts covering Expanse lore, factions,   ship capabilities, crew backstory, and immediate situation - YAML-safe fact strings (colon-in-list-item bugs fixed) UI / templates - Opening scene server-rendered at turn 0; persists across refreshes - New Game triggers page reload (no stale client state) - Markdown rendered everywhere: narrative, facts, NPC notes, inventory,   objectives, location description, PC concept (data-md + _applyMarkdown()) - Scene card: NPCs shown as named cards with description/attitude, not pills - Facts scroll box: shows latest 7 facts; count badge shows total - 4 action pills per turn (was 3–5) - Debug sidebar card: shows schema enforcement, IO logging, log file path,   recent request timings - No auto-open browser on startup; URL printed to terminal in banner Config - enforce_extract_schema: false (fast freeform extract by default) - log_llm_io: true, level: DEBUG - established_facts_max: 25 - setting_pack: expanse-belter

fails loud on bad config - POST /new-game: static -> load seed directly; dynamic -> call generate_seed() - New POST /new-game/reroll: re-rolls dynamic opening before turn 1 - run_turn() passes pack_style + pack_examples from active pack on every turn - enforce_seed_schema wired from config.yaml ## UI (index.html) - Roll Again button for dynamic packs (visible at turn 0, hidden after first action) - Commented player_overrides textarea stub wired for future use ## Packs expanse-belter (static, migrated):   - pack.yaml, style.md (Expanse tone rules)   - extract_examples.yaml (5 examples migrated out of extract_system.j2) zombie-survival (dynamic, new):   - pack.yaml, world.md (H7N9-X lore canon), style.md (survival tone)   - scenario.yaml (hard constraints + de-biased inspiration prose)   - extract_examples.yaml (3 zombie-flavored worked examples) packs/AUTHORING.md: complete spec for both modes; dual-purpose context for future generate_pack() tool ## Tests (113 total, 35 new) - tests/test_pack_loader.py: 28 tests - tests/test_generate_seed.py: 11 tests - tests/test_engine_smoke.py: new TestPackKwargs class ## Config - config.yaml: enforce_seed_schema: false - setting_pack: zombie-survival ## Pack picker UI - New Game button opens a modal listing all packs from packs/ via GET /panels/pack-picker - Each card shows name, mode badge (dynamic/static), description, and tone tags - Selecting a card posts pack_id to POST /new-game and switches the active pack - server.py: list_packs() drives the picker; _pack_id/_active_pack made mutable globals - templates/_pack_picker.html: new Jinja template for pack cards - Pack card click uses event delegation; visibility toggle uses style.display (not hidden attr) ## expanse-belter converted to dynamic pack - pack.yaml: mode static->dynamic, version 1->2, files updated to world+scenario - New world.md: Expanse hard-sci-fi canon (year 2351, physics, factions, Ceres economics) - New scenario.yaml: constraints, inspiration blocks, cliche guards incl. chronic illness ## Established facts quality overhaul (generate_seed_system.j2) - Exactly 12 facts: 5 global + 7 local (was unconstrained) - Global facts must consolidate (one entry per faction, not one per slang word) - Local facts drawn from four categories: faction/power, recent event, infrastructure, local history - Hard ban on glossary entries, character traits, NPC opinions, genre platitudes, duplication - Top-level rule: facts must teach something not inferable from the setting alone ## Cliche guards - zombie-survival/scenario.yaml: chronic illness/disability added to forbid_cliches ## Prompt rule reorganization (extract_system.j2) - Five preamble rules moved verbatim into their matching field guidance sections:   actions quality, real-names, long-term facts, remove-outdated-facts, lower-quest-bar ## Turn UX - Structured changes (inventory/player/facts/quests) from pre/post state diff; ships in turn_complete SSE - Turn summary modal: emoji-categorized sections, dismiss via Enter/Escape/click, italic hint - Chronicle pill in header: blue accent, book emoji, overlays narrative column, zero footprint closed - Stop: Send button turns red with white spinner during inference; click cancels SSE + restores state - Narrate tokens_in/tokens_out captured from streaming done chunk; stored in events.jsonl - Scrolling fixed: removed broken narrative-panel-wrap; narrative-column is position: relative - Inventory remove hardened: resolve_inventory_remove_target(), amount<=0 -> full remove - Tooltips: mouseenter/mouseleave per element (no portal bridge) - Action pills: trailing space inserted, no auto-submit - NPC notes: inline, no data-md, high-specificity CSS for 11px/muted/italic - Atmospheric scene-tags-row removed - Debug panel: simplified columns, two-line tok in/out, turns->status->errors order - CSS cache-busting: app.css?v={mtime} ## Docs - README.md: Packs section, updated file layout, rewritten How it works - CHANGELOG.md: Unreleased (2026-04-30) section
