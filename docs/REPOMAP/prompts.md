# Prompts — Jinja2 templates

## Template files

Located in `ccya/prompts/`:

- `rules_system.j2` / `rules_user.j2` — Call 0: intent classification + dice. `rules_system.j2` includes near-miss directive guidance: when a `fail` directive includes a near-miss note, the narration should describe a setback or complication that changes the situation without completely blocking the player. Explicit no-roll movement examples (pure approach/sit, item retrieval from own inventory, unimpeded corridor movement) and payment exception example (willing merchant haggling) with concrete few-shot illustrations. `rules_user.j2` context: `pc`, `location`, `recent_turns`, `user_input`, `meta`, `present_npcs`, `last_outcome` (optional string from previous turn's outcome_summary; replaces full last-turn narrative to save tokens).
- `narrate_system.j2` / `narrate_user.j2` — Call 1: prose narrative. `narrate_system.j2`: HIGHEST PRIORITY player input rule with concrete conflict example (player action first, GM beat as environment); tense authority deferred to pack style block (defaults to past tense); inventory hard constraint rule prevents narrator from inventing items not in player's inventory; null-omission output discipline rule; NO REPETITION RULE; NPC QUANTITY RULE. Campaign Arc section: receives `current_arc` context dict (visible_goal, thematic_question, phase, active_threads, pc_drive); thematic_question shapes emotional register but is never stated directly; pc_drive colors inner narration/subtext; active threads woven through environment/NPC behavior/atmosphere, never announced as objectives. Narration directives section defines: Breathe, Overwhelm, Pressure, Tension, Combat Fatigue, Location Imperative (5+ turns in location — force movement), Location Pressure (3+ turns — hint at reasons to leave), Threat Pressure (background threat lingering — acknowledge it), Resolve a Threat (old threat — resolve it narratively). `narrate_user.j2`: inventory block labeled with cross-reference reminder; collapsed structure — Immutable Reference (world state + factions + name pool), Scene Context (active threats + known characters + present NPCs + compendium bios), Recent History (up to 3 recent turns + chronicle bullets, no separate recent events), This Turn's Result (merged band directive + GM beat + momentum + pressure/age imperatives, no raw dice numbers); scene_pressure wire fix (bare variable now passed from engine); momentum floor two-tier directive (-2 softens, -3 mandatory relief); de-escalation reward on Breathe block; `world_factions`/`world_locations` wired through from pack.scenario; faction block renders `disposition` (not `alignment`); location block renders `name` + `type`; location age directive blocks restored (Pressure >2 turns, Imperative >4 turns); Threats section shows threat ages with urgency badges; threat imperative directives fire at configured thresholds (Resolve a Threat / Threat Pressure).
- `extract_scene_system.j2` / `extract_scene_user.j2` — Call 2a: scene extraction. Scoped to four responsibilities only: NPC presence, location change, scene classification (tags/tagline), location description. Explicitly forbids emitting pressure fields, inventory, conditions, quests, recent events, gm beats, world state. `scene_pressure`, `deescalate`, `quest_ages`, `active_quests` context blocks removed from user prompt (reduces prompt size, eliminates risk of LLM emitting pressure ops from context noise). NPC emission rule: conditional ambient presence — only emit ambient NPCs when no named NPCs are present. NPC ENTER/EXIT RULE (MANDATORY) with three examples (enter, exit, no-mention) governs `npc_add`/`npc_remove` emission. Standoff/confrontation scene-tag examples (standoff, intimidation, tense_confrontation) for verbal confrontations. `present_npcs` block in user prompt no longer includes NPC bios (bios remain in `npc_roster` compendium block).
- `extract_state_system.j2` / `extract_state_user.j2` — Call 2b: state extraction. Generic item mapping rule (ZERO TOLERANCE): maps generic currency/item terms (coin, silver, gold piece, etc.) to canonical inventory IDs; never invents new IDs. CONDITION DURATION GUIDE (brief/short/medium/long/Permanent taxonomy) and CONDITION RELEVANCE RULE guide condition duration assignment. Conditional `rules_stakes_hint` block injected when `stakes` and failure band present. Quantity parsing uses explicit priority hierarchy (explicit number > inference > omit). Spending/giving rule (MANDATORY) with few-shot examples mapping narration to delta including key-use removal, NPC-paying-PC addition, and vague small-payment (amount: 1) patterns; always emit `inventory_remove` when player parts with items/currency. User prompt no longer includes `pc.name` / `pc.tagline` header (state extractor does not need PC identity for inventory/condition parsing).
- `extract_progress_system.j2` / `extract_progress_user.j2` — Call 2c: progress extraction. Turn stamp injection via `## turn` block in user prompt + engine-side overwrite of `recent_events_add.turn`. Quest deduplication rule (MANDATORY) prevents near-duplicate quest creation with explicit "NEVER create" examples. Quest auto-close mandatory instruction with concrete example: emit all objectives done when all are true, engine auto-completes. NEVER emit completed quest again example prevents re-activation of completed quests. Completed-objective dedup rule (MANDATORY) prevents re-emitting already-done objectives. Contact/meet objective rule is explicit override of general no-dice-roll completion guidance. `beat_disposition`, `scene_pressure_add`, `scene_pressure_remove`, `scene_pressure_update` in output schema + field rules. Update-only guard on `scene_pressure_update`: every id must match existing pressure. scene_pressure_remove guidance: MUST emit IDs when narration shows threat resolved, including threats resolved via "Resolve a Threat" narration directive. GM Beat Grounding Rule: instruction must reference existing NPC or pressure entity. Progress user prompt: `stakes`/`band`/`deescalate`/`pending_beat`/`scene_pressure_add`/`scene_pressure` (Current Pressures block) injected before narration. Prior-turn index guard relaxed from `>= 2` to non-empty check. User prompt no longer includes `pc.name`/`pc.tagline` or `pc_stats` block (progress extractor does not need raw stat values for quest/recent-events reasoning). `last_turn_narration` truncated to last 300 characters (reduces ~2.6k tokens per run). `present_npcs`, `location`, `scene_pressure`, `inventory`, `conditions` sourced from `_ExtractionContext` (this-turn derived) rather than stale `state` dict.
- `generate_seed_system.j2` / `generate_seed_user.j2` — Seed generation for dynamic packs. System prompt: NPC ROLE ALIGNMENT RULE (conditional on scenario.factions) enforces cultural/historical consistency for NPC roles, occupations, and gender; gender guidance for combat roles (historical = male names only for combat; modern/speculative = any gender). present_npcs count is variable via `npc_count_override` Jinja variable (falls back to "Exactly 2" when 0). Hard constraints section renders from `scenario.constraints`. User prompt: `npc_generation_context` block (factions, narrator_rules, world_facts) for NPC role guidance; `npc_count` block renders player's NPC request when `npc_count_override > 0`. `seed.py` passes `min_named_npcs` from `scenario.constraints` as fallback default.
- `generate_pack_system.j2` / `generate_pack_user.j2` — Pack generation from WorldBrief (used by `pack_gen.py`)
- `generate_pack_system_wb.j2` / `generate_pack_user_wb.j2` — Pack generation from world builder inputs (flat concept/tone_tags/world_rules)
- `compact_system.j2` / `compact_user.j2` — Chronicle compaction (LLM historian, PART 1: prior-history bullets with mandatory dedup against prior_history section, PART 2: state sanitization JSON with _checklist key for verification, Pydantic-validated output contract, PART 3: recent_events consolidation — merge similar events, aim to halve count, in-universe phrasing, fresh IDs)

## Shared partials

Located in `ccya/prompts/sections/`:

- `_chronicle` — narrative history
- `_inventory` — player inventory
- `_location` — current location
- `_pc` — player character
- `_quests` — active quests only
- `_arc` — campaign arc context (visible_goal, phase, active_threads) for narrator user prompt
- `_recent` — recent events
- `_recent_events` — event list
- `_world_state` — immutable world facts
