## Critical — State integrity / long-run correctness

### C1. Compactor stagnation after initial fire
- **Turns:** 7-10
- **Pipeline:** compactor
- **Failure mode:** Compactor fires at T6 (produces bullets correctly) but produces 0 bullets and 0 sanitization actions for T7-10. `recent_events` grows unbounded (3→4→5→6→8 entries), `prior_history` becomes stale.
- **Impact:** Token bloat in long sessions, stale context, degraded extraction quality.
- **Root cause:** Compactor trigger logic likely only fires once per session, or compactor prompt lacks loop/re-trigger condition.
- **Remediation:** Review compactor trigger in `engine/compactor.py`. Ensure it runs every N turns or when `recent_events` exceeds threshold. Update compactor prompt: "Run this extraction every compaction cycle. If no new bullets are generated, still sanitize existing events and close completed quests."

### C2. Condition duplication with silent drop
- **Turns:** 7, 9
- **Pipeline:** extract_state → delta validator
- **Failure mode:** Extractor emits `pc_condition_add` for `bruised_ribs` which already exists. Validator silently drops the duplicate. Applied deltas show empty array, creating a disconnect between what the extractor thought it did and what actually happened.
- **Impact:** Extraction logs lie to downstream pipelines. State tracking becomes unreliable.
- **Root cause:** Extractor doesn't check `active_conditions` before emitting. Python validator deduplicates silently.
- **Remediation:** Add pre-check directive in `extract_state_system.j2`: "Compare proposed condition IDs against active_conditions. If an ID already exists, set pc_condition_add to null for that ID. Do not emit duplicates."

## Major — Extraction accuracy / state drift

### M1. Location change scope mismatch
- **Turns:** 8, 9
- **Pipeline:** extract_scene
- **Failure mode:** Extractor emits `location_change` with ID `crossed_keys_inn_entrance` which is identical to the previous turn's location ID. Auto-checker correctly flags: state ID didn't change.
- **Impact:** Auto-checker failures, potential state confusion.
- **Root cause:** Extractor doesn't guard on ID change. Emits location_change whenever narration describes a location, even if only the description changes.
- **Remediation:** Update `extract_scene_system.j2`: "Emit location_change ONLY if the new location ID differs from state.location.id. If only the description changes, set location_change to null."

### M2. Compendium NPC matching failure
- **Turns:** 5, 7
- **Pipeline:** extract_scene
- **Failure mode:** Extractor adds `scarred_tough` and `bald_tough` as new NPCs via `npc_add`, but compendium already contains `tough_a` and `tough_b` with matching bios. Creates duplicate identities.
- **Impact:** Schema drift, duplicate NPC entries, trust axis issues.
- **Root cause:** Extractor ignores compendium pre-check instruction. LLM doesn't match descriptors to existing entries.
- **Remediation:** Add hard constraint in `extract_scene_system.j2`: "Compare narration descriptors against compendium.npcs. If a match exists, emit npc_update with the existing ID. Never emit npc_add for known compendium entries."

### M3. Rules target hallucination
- **Turns:** 7, 9
- **Pipeline:** rules
- **Failure mode:** T7 targets `Halden` despite Halden not being in `present_npcs`. T9 maps "offer a credit to the wall" to `persuade`. System rolls charisma against absent entities and inanimate objects.
- **Impact:** Breaks forward dependency chain. Inherited by progress extractor (M4).
- **Root cause:** Rules prompt lacks strict "target must be from present_npcs" constraint. Relies on LLM self-correction.
- **Remediation:** Add constraint in `rules_system.j2`: "target MUST be an ID or name from the provided present_npcs list. If the player's intent references an absent entity, set target to the nearest present NPC or 'none' and note the mismatch in stakes." Add fallback: "If the target is inanimate or the action is physically nonsensical, set intent_verb to 'interact' or 'sneak' and set check.required=false."

### M4. Inherited intent hallucination in progress extractor
- **Turns:** 7, 9
- **Pipeline:** extract_progress
- **Failure mode:** Progress extractor outputs `intent: persuade Halden`, mirroring rules pipeline's hallucination. Receives `player_intent` from rules prompt without validation.
- **Impact:** Propagates errors across pipelines. Quest updates based on incorrect intent.
- **Root cause:** No cross-reference with `present_npcs` or `recent_events`.
- **Remediation:** Pass `present_npcs` directly to the progress prompt's intent grounding section. Instruct extractor to override `player_intent` if it references absent entities.

## Minor — Token efficiency / prompt quality

### N1. Scope over-flagging by narrator
- **Turns:** 4, 8, 9
- **Pipeline:** narrate
- **Failure mode:** Narrator flags `pc_condition` and `inventory` in scope even when no change occurs. Prompt says "bias towards inclusion" but forces unnecessary extractor runs.
- **Impact:** Wasted tokens (~1000-1500 per unnecessary extractor invocation), increased parse risk.
- **Remediation:** Tighten scope instruction: "Only flag inventory or pc_condition if the narration explicitly confirms a gain, loss, or condition change. Do not flag them for mere mentions or environmental descriptions."

### N2. Recent event bloat
- **Turns:** 7-10
- **Pipeline:** extract_progress
- **Failure mode:** Progress extractor adds redundant events. Combined with compactor stagnation (C1), `recent_events` grows from 3 to 8 entries without culling.
- **Impact:** Token bloat in progress prompt (~150-200 tokens per extra event), compounds across turns.
- **Remediation:** Add directive in `extract_progress_system.j2`: "Limit recent_events_add to 1-2 per turn. Prioritize events that change quest status, introduce new threats, or reveal NPC allegiances. Omit redundant tracking events."

### N3. Prompt redundancy: recent_events duplication
- **Turns:** all
- **Pipeline:** narrate + progress overlap
- **Failure mode:** `recent_events` block duplicated verbatim in narrate and progress prompts. Wastes ~150-200 tokens per turn.
- **Impact:** Cumulative token waste (~2000 tokens over 10 turns).
- **Remediation:** Replace full `recent_events` list in progress prompt with compressed summary surface (e.g. "T1: Met Caron. T2: Paid debt.").

## Cross-Cutting Themes

1. **Extractor grounding is the weakest link.** All three extractors suffer from insufficient cross-referencing against current state. Scene doesn't check compendium, state doesn't check active conditions, progress doesn't check present NPCs.
2. **Compactor lifecycle is broken.** Single-fire behavior leaves recent_events unbounded. This is the highest-leverage fix for long-run stability.
3. **Silent failures hide bugs.** Condition dedup happens in the validator invisibly. Extractor thinks it succeeded. Downstream pipelines see different state than expected.
4. **Auto-checker needs precision tuning.** NER is catching non-NPC tokens. Some assertions (`rules.rolled`) may have logic bugs.
