## Severe

### S1 [v] — `load_state` silently nukes a save on any YAML problem
`ccya/state/io.py:34-52`. Missing file, *any* `yaml.YAMLError`, or an empty file all return `default_world_state()` (blank game) with only a log line. The next turn then runs on the blank state and `save_state()` (atomic tmp + `os.replace`, :55-62) overwrites the file — one corrupted byte in `state.yaml` (manual edit, merge, another writer) and the entire game is gone. No `.bak` rotation, no raise, no "state unparseable → refuse turn" behavior.
Refinement: the asymmetry is partial-loud/partial-silent. A *structurally* invalid save (missing/damaged fields) propagates out of `WorldState.from_dict(raw)` (:52) as `ValidationError` — loud but a 500 at turn start; while *YAML-level* corruption is the silent-loss path. Either way the consequence class is "lose the whole game." Highest-consequence finding in the codebase.

### S2 [v] — NPC compendium keys written under three different normalization rules → duplicate entries
Same entity can enter `compendium.npcs` under three spellings:
1. **Normalized** — `state/npcs.py:41,94` (`apply_npc_scene_management`, add path and update path) both run `normalize_inventory_id()` (spaces/hyphens→`_`, non-alnum stripped, `state/inventory.py:36`) before `add_npc`/`update_npc`. This path is fully normalized.
2. **Raw** — `engine/turn_state.py:528-545` ("stamp touched NPCs" loop) iterates the **same** `delta.compendium_npc_update` list *after* path 1 has run, and uses the **raw** `cu.id` for `get()` (:531), `add_npc()` (:537 — `WorldState.add_npc`, `models/state.py:242-245`, does **no** normalization), `update_npc()` (:539 — silent no-op via `if npc_id in npcs` at :249), and `generate_npc_color()` (:536).
3. **lower+strip, spaces preserved** — `extraction/utils.py:107` (`_dedup_compendium_update` case 1: `proposed_id in existing_ids`) — a third rule that compensates for none of the above and never matches a normalized multi-word key.

Consequences (concrete, not hypothetical): an LLM id like `"Baron von Cold"` → path 1 writes `baron_von_cold`; path 2 then does `get("Baron von Cold")` → miss → `add_npc("Baron von Cold", NPCEntry(name="Baron Von Cold" ...))` — a **second** entry with the raw key, a fabricated title-case name built from the id, and a different generated color, sitting beside the real one. Roster doubles; presence/party flags split. And for every *existing* NPC whose normalized key ≠ raw id, the `update_npc` branch silently no-ops → `last_presence_turn` stops advancing for exactly the multi-word NPCs. The dedup in utils is a compensation for the missing boundary normalization, which is why it never quite matches.
Fix (one shape): normalize id once at the extraction boundary (utils `_coerce_*`/dedup) so every downstream touch point — including the turn_state stamp loop — sees one keyspace; delete the other two rules.

### S3 [v, rewritten] — The turn lock is a phantom: it is replaced every turn, so it never serializes anything
The module docstring (`server/app.py:6-16`) claims *"All callers of run_turn (ws/turn, play.py) acquire the **same** lock, serializing turns per-save."* False. Verified mechanism:
- `app.py:30`: `_turn_lock: asyncio.Lock | None = None`; `:36-41` `_start_turn()` creates a **fresh** `asyncio.Lock()` + two fresh `asyncio.Event`s and assigns all three to module globals.
- `engine/turn.py:103-105`: every `run_turn` body calls `_start_turn()` (replacing the globals) then `await _turn_lock.acquire()` — on a **new, unheld** lock, which can never block. The lock serializes nothing.
- `app.py:44-53` `_signal_turn_done()` (called from `turn.py:321` in `finally`) sets done+cancel events, releases the lock, nulls all three globals.

Real hazard, two faces:
1. **TOCTOU at the route.** The only concurrency gate is `routes.py:243` `if _app_mod._is_turn_in_progress(): return _busy()` — checked *before* `run_turn()`'s deferred body creates the lock. Two close-together `POST /turn` requests both see not-in-progress, both start, each `_start_turn()` swaps in its own fresh lock, both run: two `save_state()` atomic renames (last writer silently wins — one turn's state changes **lost from the save**), two `## Turn N` chronicle headers for the same number, interleaved `events.jsonl` rows.
2. **Cross-wired globals.** Because every turn *replaces* the module-global lock/events, two overlapping turn generators share one set of globals: a lagging first turn's `finally: _signal_turn_done()` sets the *second* turn's done event (early return from `_await_turn_done`) and its cancel event; `_set_turn_result`/`_get_turn_result` (the mobile reconnect feature, `routes.py:316/423-426`) can hand the wrong turn's result — or `None` — to a reconnecting client. The docstring's "in-place update" comment assumes a stable object; the code swaps it.
Also entangled: `engine/turn.py:103` imports `ccya.server.app` **at runtime from inside the engine package** (circular-dependence workaround), and importing `ccya.server.app` executes module-level `_find_latest_save()` (scans `saves/` + `evals/runs/`) and `FastAPI()` construction — so `ev/play.py` (and any offline tool importing `run_turn`) drags the server stack and a directory scan into its import graph.
Fix shape: one process-lifetime lock/event set (created at server startup, never replaced); acquire **in the route handler** before starting the stream; release in `finally`; delete the engine-side `_start_turn` import (inject a session object).

### S4 [v] — `trim_messages` can't reach its budget and corrupts the window guard
`ccya/llm_client.py:523-551`. The loop picks the first non-system message, then:
- `budget <= 0` → `messages.pop(idx)`, recompute, **continue** (so several small messages *can* be dropped — that part works);
- `budget > 0` → truncate head 2000 / tail 500 chars, then unconditionally `total = max_tokens + 1  # exit loop` (:551) — **even if the truncate was a no-op** (`head_keep + tail_keep >= len(content)` → content untouched, :543) **and even if dropping several remaining small messages would fit**.

So the moment it meets a too-big message, the loop exits *still over budget* — the "trim" did nothing, and every such call expands past `context_window` (32k) while `num_ctx` tells the LMStudio server it has 16k → real truncation on the LLM side, silent. Messages are also mutated **in place** (`messages.pop`, `msg["content"] = ...`) — callers share the list object with the retry/tracing paths. The chars/3.5 estimator is fine; the loop structure is simply incapable of producing a result that satisfies the invariant it claims (`was_truncated`, :553 is even computed from a no-op-premise "removed 0 chars" lie in the no-op case).

## Cross-cutting smells worth naming once

- **Two worlds of "state":** a typed `WorldState` *and* a dict/Any layer (`dict[str, Any]` pervades changes/sanitizer/pipeline/record, plus the StateMerge≅StateExtractResult shape duplication, L1) — every boundary between them is an `isinstance(x, dict)` / `getattr(x, "id")` bridge. The typing pass went one module deep and stopped.
- **Dead code is the default**: `deescalate` (L6), `npc_roster` param (L10), `turn.py:98/302` list (M6), `WorldStateFact` twins (L1), `state_delta` (L15), the `if arc:`/malformed-thread branches (L8), the mock import (L9), the dangling `init_save_dir` comment (L4) — zero TODOs in the repo, and at least 8 unreachable/vestigial constructs; nothing flags them because nothing references them.
- **Three LLM I/O regimes**: `chat()` 1200s config timeout + ccya-typed errors, `chat_stream()` same timeout + *raw* SDK errors (M1), and per-call 60/30s hardcodes in world/turn — one policy, three implementations, and the stream side bypasses the graceful error path.
- **Whole-file I/O on the turn hot path** (L3 + M7): every turn does O(game-so-far) reads of `events.jsonl` and `chronicle.md`, plus two full rewrite passes of the chronicle, and appends a full-state snapshot — the save directory is its own scalability wall.
