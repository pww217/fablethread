---
name: ev-review
description: Retrospective analysis of eval runs and player saves
---

Purpose: Inspect existing saves for bugs, regressions, and quality issues. Produces a report and files candidate bugs as `new` in the roadmap.

## Sources

- **Eval run dir:** `evals/runs/<group>/<run>/` (has `run-meta.yaml`, auto-generated `report.md`)
- **Player save dir:** `saves/<name>/` (no metadata, created by web UI)
- **Group-level:** `evals/runs/<group>/REPORT.md` (consolidated report across multiple runs)

## Workflow

1. **Load save & metadata** — read `run-meta.yaml` (if eval run) or infer scenario/personality from the directory name
2. **User guidance** — the user specifies what to focus on: "look at the consolidated report", "investigate pacing in noir-1930s", "check thread resolution", or general "find anything concerning"
3. **Run full rubric:**
   - Deterministic checkers: `.venv/bin/python scripts/debug/ev.py check --all --save-dir <path>`
   - LLM checkers: targeted runs on flagged turns
   - Subjective qualitative analysis: narrative flow, pacing, convergence, character consistency
4. **Write report** — structured analysis at the save/group level covering checker results, qualitative findings, and comparison against prior runs
5. **Extract bugs** — for each confirmed issue, create `roadmap/bugs/<slug>.md` with `status: new`

## Bug Extraction Format

```yaml
---
title: Descriptive title
status: new
created: YYYY-MM-DD
labels:
  - eval
  - <component>    # engine, prompt, checker, narrative, pacing, etc.
---
Reproduction context: save path, turn number, checker output, relevant event data.
Root cause estimate (if identifiable): ...
```

The bug is filed as `new` — not yet validated. `bug-triage` handles validation.

## What NOT to Do

- Do not generate per-run `report.md` files — those are auto-generated by `ev.py`.
- Do not overwrite existing bug files — create new slugs for new issues.
- Do not set severity or urgency — those are for `bug-triage` to assess.

## Spot Checks

On request, run targeted analysis on specific mechanics or turns:
- `ev.py turn <N>` — full dump of a specific turn
- `ev.py mechanics <N> --dice --pacing` — roll math and beat timing
- `ev.py threads --summary` — thread lifecycle analysis
- `ev.py trace <field.path>` — track a state field across turns
