# Bias Storyteller Choices Toward Forward Momentum

## Purpose

Make choices generated by the storyteller extractor action-oriented, arc-relevant, and faster-paced instead of random/passive.

## Problem Statement

Storyteller-generated player choices tend to be generic, passive ("look around", "plan carefully"), and disconnected from story momentum. The prompt has structural rules (four categories) but no enforcement that those categories should produce forward-moving, escalating options. Pacing context exists in the user prompt but is not connected to choice generation at all.

## Constraints

- Only modify `ccya/prompts/storytell_system.j2` — no code changes.
- Do not remove or alter fallback action generation (user explicitly excluded it).
- Preserve existing structural rules: four-choice categories, latent thread steering guidance, pacing context section unchanged for beats/threads.
- Keep choices at ~10 words each; do not change length constraints.

## Non-goals

- Fallback action improvements (explicitly out of scope per user request).
- Changes to `storytell_user.j2` or `_arc.j2`.
- Changes to extraction pipeline code (`extraction.py`).
- Adding new prompt sections for outcome_summary, threads, arcs, beats.

## Solution

Two edits to the storyteller system prompt: (1) strengthen line 28 with explicit action bias, emotional posture diversity, PC voice rule, and generic verb avoidance; (2) add a "Choice momentum" section after latent thread guidance that connects pacing context directly to choice generation and tells the LLM to escalate from prior turns.

## Firm decisions

1. All changes go in `ccya/prompts/storytell_system.j2` only — single file, single phase.
2. Line 28 gets an expanded actions instruction block replacing "Bias to bold, good storytelling choices." with concrete rules borrowed from the seed prompt and new action-pacing language.
3. A new section titled "## Choice momentum" is inserted after line 88 (latent thread guidance) and before line 90 ("## PacingContext guidance"). It tells the LLM how pacing directives should influence choice tone/urgency, and instructs building on prior turn history for escalating stakes.
4. Existing sections are unchanged: actions structural rules preserved, latent thread guidance preserved, PacingContext guidance for beats/threads preserved.

## Risks, Ambiguities, and Blockers

- **Risk:** Adding too much instruction to line 28 could cause prompt bloat or conflict with existing four-choice structure wording. Mitigation: append after the existing sentence starting "Bias to bold..." rather than rewriting the whole paragraph; keep additions concise (~3 sentences).
- **Ambiguity:** How explicit should PC voice be? The seed prompt says "written from the PC's point of view or voice." Storyteller choices are suggestions, not direct commands. Resolution: phrase as "Write choices in active voice as if spoken by the PC" — directive but not prescriptive about first-person vs second-person phrasing.
- **Validation:** No automated tests exist for prompt quality (tests temporarily removed). Verification is manual inspection of generated choices after deployment.

## Implementation — Phase 1: Strengthen storyteller prompt for action-oriented choices

### Detailed steps

#### Step 1.1 — Expand actions instruction on line 28

**File:** `ccya/prompts/storytell_system.j2`, line 28

**What:** Replace the sentence starting with "Bias to bold, good storytelling choices." and ending at "**You MUST always emit..." with a stronger block that includes:
- Forward momentum rule: each choice must escalate consequences, force a decision, or change the situation irreversibly; avoid passive options like "look around", "wait and watch", "plan carefully"
- Emotional posture diversity: the four choices must span different postures (confront vs negotiate vs flee vs exploit) not variations of the same approach  
- PC voice rule: write choices in active voice as if spoken by the PC; avoid generic filler that could fit any protagonist in any setting

The replacement text should be inserted after "Examples: \"Aim for the chest and fire\", \"Convince the guard to let you pass\"." and before "**You MUST always emit exactly 4 non-empty strings..."

**Why:** The current prompt has structural rules but no enforcement that choices should move the story forward. These three additions (momentum, posture diversity, PC voice) are proven mechanisms from the seed prompt plus new action-pacing language.

**Validation:** Read back line 28 after edit to confirm: four-choice structure intact, examples preserved, "You MUST always emit" sentence unchanged at end, no markdown formatting issues.

#### Step 1.2 — Add Choice momentum section after latent thread guidance

**File:** `ccya/prompts/storytell_system.j2`, after line 88 (before line 90)

**What:** Insert a new section titled "## Choice momentum" between the existing text on line 88 and "## PacingContext guidance". The section should contain:

> **Escalate from prior turns.** Look at what happened in recent turns — choices should escalate or complicate what came before, not repeat it. If last turn was combat, this turn's options might involve consequences of that fight (pursuing wounded enemies, looting bodies, dealing with reinforcements).
> 
> **Pacing and urgency:** When the directive is "Overwhelm" or "Pressure", choices should reflect escalating stakes — urgent, time-sensitive options that demand immediate action. When the directive is "Breathe", allow investigative or exploratory choices but still avoid passive stalling ("wait", "observe"). Never let a choice sit at zero tension for more than one turn in an active arc.

**Why:** Pacing context (`directive`/`gate`) is already injected into user prompt and used for beats/threads, but not connected to choice generation. This section bridges that gap. The prior-turn escalation rule leverages the existing `prior_history` variable which is currently underutilized for choice guidance.

**Validation:** Read back lines 85-96 after edit to confirm: new section properly delimited with "## Choice momentum" heading, blank line before and after, PacingContext guidance unchanged starting at what was originally line 90 (now shifted down by ~2 lines), no duplicate headings.
