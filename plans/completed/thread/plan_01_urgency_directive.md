# Plan 01: Urgency Directive

## Status
completed

**Replaces:** `scene_pressure` lifecycle + `location_imperative` directive

---

## Problem

`scene_pressure` and `location_imperative` are two systems doing the same job from adjacent angles. `scene_pressure` manages a lifecycle of named threats (add/update/remove, urgency levels, turn tracking). `location_imperative` is a separate narration directive fired by age threshold that tells the narrator "move this shit along" when the player has been in one place too long.

Both ultimately produce one signal to the narrator: *something is demanding movement*. The narrator receives them via different template sections and has to reconcile them. There's no reason they can't be one thing.

`Location Imperative` and `Location Pressure` currently live as raw directive strings in `narrate_user.j2` generated by age-threshold logic inline in the template. They have no state identity, no lifecycle, no ID — they fire and vanish. That's the real problem: they're not a parallel system at all, they're just a band-aid for the fact that `scene_pressure` can't model "the story itself is stalling."

---

## Solution

Introduce a new pressure urgency value: **`pacing`**. This is not a threat in the fiction — it is a GM-level signal that the narrative needs to move. The narrator is already told (in system) to read urgency and respond accordingly. A `pacing` pressure gets rendered identically to an `immediate` pressure for the narrator, but its *meaning* is different: it's not an in-world danger, it's a structural demand.

`location_imperative` and `location_pressure` become auto-managed pressures injected by the engine, not inline Jinja logic.

### New urgency level

```python
class PressureUrgency(str, Enum):
    BACKGROUND = "background"
    BUILDING   = "building"
    IMMEDIATE  = "immediate"
    PACING     = "pacing"   # NEW — GM-level structural demand, not in-world threat
```

### Auto-injection logic (replaces inline Jinja)

In `tick_ages()` or equivalent:

```python
LOCATION_PRESSURE_AT  = 3  # turns
LOCATION_IMPERATIVE_AT = 5  # turns
PACING_PRESSURE_ID = "__pacing_location"

def update_location_pacing(state: GameState) -> None:
    age = state.ages.get("location_age", 0)
    existing = next((p for p in state.scene.scene_pressure if p.id == PACING_PRESSURE_ID), None)

    if age >= LOCATION_IMPERATIVE_AT:
        text = (
            "MOVE THE STORY. The player has been here too long. "
            "Force movement now: a character arrives with urgent news, "
            "a deadline triggers, or the environment makes staying untenable."
        )
        urgency = PressureUrgency.PACING
    elif age >= LOCATION_PRESSURE_AT:
        text = (
            "Begin winding down this location. "
            "Hint at a reason to leave — a closing window, a lead elsewhere, "
            "a local shift that makes staying less compelling."
        )
        urgency = PressureUrgency.PACING
    else:
        # Under threshold — remove pacing pressure if it exists
        if existing:
            state.scene.scene_pressure = [
                p for p in state.scene.scene_pressure if p.id != PACING_PRESSURE_ID
            ]
        return

    if existing:
        existing.text = text
        existing.urgency = urgency
    else:
        state.scene.scene_pressure.append(ScenePressure(
            id=PACING_PRESSURE_ID,
            text=text,
            urgency=urgency,
            turn_added=state.meta.turn,
        ))
```

The pacing pressure is auto-removed when location age resets (player moves).

## Template changes

### `narrate_user.j2` — remove

Delete the entire location age / location imperative Jinja block (currently ~10 lines):

```jinja2
{# REMOVE THIS ENTIRE BLOCK #}
{% if ages and ages.get('location_age', 0) > 4 %}

**Narration Directive:** Location Imperative
...
{% elif ages and ages.get('location_age', 0) > 2 %}

**Narration Directive:** Location Pressure
...
{% endif %}
```

The pacing pressure will appear in `## Active Threats` through the normal `scene_pressure` rendering path. No special case needed.

### `narrate_system.j2` — update directive definitions

In the `## Narration directives` section, **remove** the `Location Imperative` and `Location Pressure` bullet definitions entirely.

Add a new bullet under the urgency-level descriptions:

```
- **[PACING]** — This is a structural demand from the GM, not an in-world threat. The story needs to move. 
  Treat it like an immediate pressure on the narrative itself: introduce a development that forces progress 
  or a location change. Do not describe this as a threat to the player — frame it as story causality 
  (a messenger arrives, a timer expires, an opportunity closes). Resolve and remove it as you would any immediate threat.
```

### `sections/_scene_pressure.j2` — new section file

Currently `narrate_user.j2` renders scene pressure inline. Extract to a section:

```jinja2
{# sections/_scene_pressure.j2 #}
{% if state.scene.scene_pressure -%}
## Active Threats
{% for p in state.scene.scene_pressure -%}
- [{{ p.urgency | upper }}] {{ p.text }}
{% endfor -%}
{% endif %}
```

Then in `narrate_user.j2`, replace the inline block with:
```jinja2
{% include "sections/_scene_pressure.j2" %}
```

This also applies to `extract_progress_user.j2` which already renders pressures inline — same extraction applies.

---

## What the extractor needs to know

The extractor already handles `scene_pressure_add/update/remove`. The pacing pressure ID (`__pacing_location`) is engine-managed and should **never** be emitted by the LLM extractor. Add a guard note in `extract_progress_system.j2`:

```
`scene_pressure_remove`/`scene_pressure_update`: Do NOT emit changes for pressures 
whose id begins with `__` — those are engine-managed and auto-resolved.
```

---

## What gets deleted

- `location_imperative` as a Python variable passed to templates — removed from `build_narrate_payload()`
- The `Location Imperative` and `Location Pressure` named directives in system prompt
- The inline location-age Jinja block in `narrate_user.j2`
- The `location_imperative_at` and `location_pressure_at` config keys (replaced by `LOCATION_PRESSURE_AT` / `LOCATION_IMPERATIVE_AT` constants used by the injection function)

---

## Migration

No state migration needed. Existing `scene_pressure` lists in saved games are unaffected — the pacing pressure will be freshly injected on the next tick if the age threshold is met. There is no backward-incompatible schema change.
