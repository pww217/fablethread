# Fix Arc System Mechanics

## Status
`completed`

## Phases
3 phases: fix all gaps between `arc-system-mechanics.md` plan and actual implementation — data model, arc director logic, narrator context, and UI visibility.

## Objective
The arc system implementation has 8 gaps vs. the design spec in `arc-system-mechanics.md`. `hidden_truths` are visible to the player at turn 0 (should never be shown). The arc director uses wrong thresholds for momentum bias, recency, and expiry. The `candidate_opportunity` flow from extraction → arc director is broken. `CampaignArc` is missing `pc_drive`. The narrator system prompt lacks `thematic_question` and `pc_drive` guidance. This plan fixes all of them.

## Non-goals
- Do not add a truth-promotion mechanism (that's a separate feature)
- Do not add `pc.expressed_stances` UI display (already wired in engine, just not shown)
- Do not add arc phase visual indicator to UI
- Do not modify `CampaignArc.phase` transition logic (stays at "setup" for now)
- Do not add `discovered_truths` promotion logic — just add the field and wire UI to show it instead of `hidden_truths`

## Firm decisions
1. `hidden_truths` must never appear in any template rendered to the player. They are designer-only structural spine.
2. `discovered_truths` is a new field on `CampaignArc` — starts empty, stays empty until a future truth-promotion mechanism is added. UI shows it, not `hidden_truths`.
3. `pc_drive` lives on `CampaignArc` model (not `state.pc.drive`) — it's part of the arc, not the PC. The seed prompt already generates it separately; we wire it into the arc.
4. Arc director thresholds match the spec exactly: momentum `>= 2` / `<= -1`, recency `> 5`, expiry `>= 8 turns`.
5. `tick_arc()` accepts a `candidate: str | None` parameter and creates a latent thread from it.
6. `_narrate_messages()` builds `current_arc_ctx` as a pre-rendered dict (per spec) and passes it to templates.
7. Narrator system prompt gets a `Campaign Arc` section with `thematic_question` and `pc_drive` guidance.

## Conflicts and overlap
- `plans/quest-story-arc-revamp.md` — original arc plan. This supersedes its implementation details where they conflict. The plan doc itself is not modified.
- `plans/replace-quest-ui-with-arc-ui.md` — UI changes already done. This plan only fixes the `hidden_truths` visibility bug in that UI.
- `plans/arc-system-mechanics.md` — this IS the spec. This plan implements it.

#### Step 2.1 — Fix momentum thresholds in `_salience_score()`

**File:** `ccya/engine/arc.py`

**What:** Lines 56-63 — change momentum bias logic:
- Low momentum: `momentum <= -1` (not `momentum < 0`)
- High momentum: `momentum >= 2` (not `momentum > 0` / `else`)

**Why:** The spec says "if `momentum >= 2`, prefer cost/deadline/complication/betrayal_risk; if `momentum <= -1`, prefer aid/breathing_room/ally/resource." Current code fires on any negative/positive momentum, which is too aggressive. The spec uses these thresholds to distinguish "slightly negative" from "at floor" and "slightly positive" from "strongly positive."

**Code Snippet** — Replace lines 56-63:
```python
    # Momentum bias
    if momentum <= -1:
        # Low momentum: prefer aid/breathing_room/ally/resource
        if any(t in thread.tags for t in ("aid", "breathing_room", "ally", "resource")):
            score += 2.0
    elif momentum >= 2:
        # High momentum: prefer cost/complication/deadline/betrayal_risk
        if any(t in thread.tags for t in ("cost", "complication", "deadline", "betrayal_risk")):
            score += 2.0
```

**Validation:** With `momentum=0`, no bias is applied. With `momentum=-1`, aid tags get +2. With `momentum=1`, no bias. With `momentum=2`, cost tags get +2.

#### Step 2.2 — Fix recency threshold in `_salience_score()`

**File:** `ccya/engine/arc.py`

**What:** Line 66 — change `last_offered_turn < turn_no - 3` to `last_offered_turn is None or current_turn - last_offered_turn > 5`.

**Why:** Spec says "Not recently offered (`last_offered_turn is None or current_turn - last_offered_turn > 5`) → +1." Current code uses threshold 3, which promotes threads too aggressively. The spec uses 5 to give threads a proper rest period.

**Code Snippet** — Replace line 66:


**Validation:** A thread offered at turn 10 gets +1 at turn 16+ (not turn 14).

#### Step 2.3 — Fix thread expiry threshold in `tick_arc()`

**File:** `ccya/engine/arc.py`

**What:** Lines 131-135 — change expiry logic from "6+ ignored signals" to "8+ turns of only ignored signals."

**Why:** Spec says "For each active thread where `last_offered_turn` is set and `current_turn - last_offered_turn >= 8`, and all its signals were `ignored`." Current code checks `count >= 6` which is a signal count, not a turn count. A thread could get 6 ignored signals in 6 turns (1 per turn) or 6 signals in 2 turns (3 per turn — unlikely but possible if signals accumulate). The spec measures in turns, not signals.

**Code Snippet** — Replace lines 131-142:
```python
    # Process thread expiry (8+ turns of only ignored)
    threads_to_expire = []
    for sig in signals:
        if sig.signal != ThreadSignalType.IGNORED:
            continue
        for t in arc.active_threads:
            if t.id == sig.id and t.last_offered_turn is not None:
                if turn_no - t.last_offered_turn >= 8:
                    threads_to_expire.append(t.id)
                    break

    for tid in threads_to_expire:
        for i, t in enumerate(arc.active_threads):
            if t.id == tid:
                t.state = ThreadState.EXPIRED
                arc.active_threads.pop(i)
                arc.completed_threads.append(t)
                break
```

**Why this approach:** Instead of tracking ignored counts separately, we iterate signals for IGNORED type and check `last_offered_turn` directly against the 8-turn threshold. This matches the spec's "current_turn - last_offered_turn >= 8" exactly.

**Validation:** A thread ignored from turn 1 to turn 8 (8 turns) expires. A thread ignored from turn 1 to turn 7 (7 turns) does not expire.
