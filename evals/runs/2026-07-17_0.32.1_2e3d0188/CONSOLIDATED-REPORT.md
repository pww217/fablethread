**SHA:** 2e3d0188 (tag 0.32.1)
**Runs:** 6 across 5 packs, 25 turns each (1 crashed at T17 due to seed generation; 1 partial: space-western:explorer completed 15 turns instead of 25)
**Date:** 2026-07-18

## Executive Summary

All deterministic checkers pass (97.7-100%). The system is mechanically sound but narratively hollow. Core findings:

- **Condition TTL bug (P0):** Conditions never expire via TTL due to dead code at `turn_state.py:443`
- **Beat-to-narration disconnect:** Alignment is 8-16% across all runs. Beats are generated but ignored by the LLM
- **Dampening loop:** Sanitizer only downgrades urgency, never escalates. Zero escalations across all runs
- **Implicit thread creation:** Seeded threads bypass thread_add gates (cooldown, cap eviction). Not implicit creation via thread_update — the code explicitly skips unknown IDs. New threads use explicit thread_add.
- **Convergence is flat:** Typical range 0-3. beat_streak dominates, urgent_thread is almost always 0
- **Convergence hard gate uses smoothed score, phase transitions use raw score** — no functional bug, but code clarity issue

The system's mechanics work correctly in isolation, but cross-cutting interactions create a stable low-tension baseline that compresses CLIMAX phases and limits pacing variety.

**Effort:** Small
**Files:** `ccya/engine/turn_state.py:443`

## 2. CRITICAL — Beat-to-Narration Disconnect ✅ VALIDATED

**Severity:** CRITICAL
**Effort:** Small (prompt change)
**Files:** `ccya/prompts/narrate_system.j2`

**What:** Beats are generated by the World step and passed to the narrate prompt as `pending_gm_beat`, but the LLM ignores them 84-92% of the time. Alignment is 8-16% across all runs (0% in noir-1930s).

**Root cause:** The narrate prompt calls beats "creative guidance — use as texture, not direction." This is explicit permission to ignore them. Confirmed at `narrate_system.j2:11`, `:76`, and `:85`.

**Impact:**
- Beats persist 2-13 turns without being consumed (noir: `gilded_lily_confrontation` persists T15-T25 = 11 turns)
- GM beats have empty `npcs` arrays — world layer has no NPC roster to associate with beats
- Narrative loops: without new beats or setbacks, narratives loop on the same content (noir T10-T17: Gilded Lily confrontations)
- Pacing pipeline is broken: beats drive convergence mechanically but are narratively invisible

**Additional context from validation:** Empty GM beat NPC arrays vary significantly across runs (0-72%, avg ~30%), not universally empty. The world layer does NOT receive the NPC roster (confirmed in DEEPDIVE-04 §4.4.3 and ruling_narration_and_npcs.md §8.4) — beats generated without NPC context cannot reference specific NPC psychology, which is a root cause of low beat alignment. Golden-piracy 25t has 0% empty beat NPC arrays (the most "healthy" run), while allied-ww2 has 72%.

**Fix:** Change "creative guidance" to "MANDATORY scene element" and require the LLM to weave beats into the narration.

**Refs:** ruling_narration_and_npcs.md §3.3, §3.12, §8.4; DEEPDIVE-01 §1.2, §1.4; DEEPDIVE-04 §4.4.6; validation-B-results.md

## 3. CRITICAL — Dampening Loop (Sanitizer Only Downgrades) ✅ VALIDATED

**Severity:** CRITICAL
**Effort:** Medium (prompt + logic change)
**Files:** `ccya/engine/thread_sanitizer.py`, `ccya/prompts/sanitize_thread.j2`

**What:** Zero urgency escalations across all 5 runs. Every sanitizer urgency change is a downgrade (urgent → normal). The sanitizer acts as a **tension damper, not a tension amplifier**.

**Lifecycle:** Record assigns urgency only during CLIMAX or when threats feel "immediate/imminent" → Sanitizer downgrades on every 5-turn cycle → A thread stays urgent for 1-2 sanitizer cycles (5-10 turns) → Convergence drops.

**Impact:**
- `urgent_thread` component (0-2 points, highest-value in convergence formula) is almost always 0
- Creates feedback loop: downgrades → low convergence → beat_streak dominates → convergence stays at 0-3
- Extensions only fire when LLM is unusually aggressive with urgency (2 of 5 runs extended CLIMAX)
- noir-1930s stays in RISING for 22 turns before reaching CLIMAX at T25

**Cross-cutting:** This is the primary mechanism behind the narrow convergence distribution. It interacts with BREATHER (amplifies reset), CLIMAX extensions (suppresses them), and convergence scoring (inverts intended weighting).

**Fix:** Add urgency escalation guidance to `sanitize_thread.j2`. If a thread was set urgent by Record within the last 2 turns, the sanitizer should preserve that urgency.

**Additional context from validation:** `sanitize_thread.j2:62-64` instructs "Urgency wrong?" without specifying direction. No escalation guidance exists. Sanitizer urgency changes across runs: noir (2 downgrades), space-western (6), golden-piracy (3), zombie-survival (4), allied-ww2 (2). Total: 0 escalations, 17 downgrades. The `urgent_thread` component averages 0.40-0.60 across runs (10-15/25 turns at 1), confirming it rarely contributes to convergence.

## 5. HIGH — Convergence Score Has Limited Dynamic Range ✅ VALIDATED

**Severity:** HIGH
**Effort:** Medium (threshold adjustments)
**Files:** `ccya/engine/_pacing.py`

**What:** The convergence score rarely exceeds 3-4. Typical range is 0-3, with most turns at 1-2.

**Component breakdown across all runs:**
- `beat_streak`: Always 0 or 1. Frequently 1 (2/4 threshold with carry-over is too easy)
- `threat_thread`: Frequently 0 or 1
- `urgent_thread`: Almost always 0 (dampening loop)
- `roll_starvation`: Almost always 0 (rolls happen frequently)
- `threat_density`: Always 0 (never 3+ active threat threads)

**Impact:**
- CLIMAX is entered as soon as beat_streak + threat_thread align (score 2)
- Extended CLIMAX requires urgent_thread to appear, which is rare
- The phase engine works correctly but the convergence score has limited differentiation between "building tension" and "high tension"
- allied-ww2 has the tightest distribution (max=3, mean=1.7); space-western the widest (max=5, mean=2.5)

**Cross-cutting:** This inverts the design intent where thread urgency should be the primary convergence signal. Beat_streak is doing the heavy lifting.

**Additional context from validation:** Convergence distribution across all 5 runs (25t): noir (0.38-2.44), space-western (0.30-2.58), golden-piracy (0.28-2.44), zombie-survival (0.26-2.36), allied-ww2 (0.22-2.58). Threat density averages: noir 0.04, space-western 0.16, golden-piracy 0.06, zombie-survival 0.00, allied-ww2 0.00. The convergence formula's intended range of 0-9 is compressed to 0-3 in practice.

**Fix suggestions:**
1. Lower `threat_density` threshold from 3 to 2
2. Lower `roll_starvation` threshold from 3 to 2 turns
3. Raise `beat_streak` threshold from 2/4 to 3/4 or remove carry-over

**Refs:** DEEPDIVE-02 §2.4; DEEPDIVE-01 §1.4; pacing.md §3.1, §4.1; validation-A-results.md

## 6. HIGH — Convergence Hard Gate Uses Smoothed Score, Phase Transitions Use Raw ✅ VALIDATED

**Severity:** HIGH
**Effort:** Trivial (code alignment)
**Files:** `ccya/engine/narrate.py`, `ccya/engine/_pacing.py`

**What:** `_compute_scene_phase()` receives the **raw** convergence score for phase transitions. `_compute_pacing_context()` receives `int(smoothed_convergence)` for the outcome_hint hard gate. The checker validates raw score, but the actual decision uses smoothed.

**Functional impact:** Since smoothed >= raw when scores are increasing (EMA lags behind), if raw >= threshold, smoothed is also >= threshold. No functional bug. However, the checker can't detect if a transition happened based on smoothed score alone.

**Additional context from validation:** `_pacing.py:132` uses `raw_convergence` for phase transitions. `_pacing.py:140` uses `int(smoothed_convergence)` for outcome_hint hard gate. The smoothed score uses EMA with alpha=0.3, so it always lags behind raw when scores are increasing. This means outcome_hint transitions happen later than phase transitions. In noir-1930s 25t, phase transitions happen at T1 (BREATHER→RISING), T22 (RISING→CLIMAX), but outcome_hint never fires because smoothed never reaches 5 (max smoothed ~3.2). This is confirmed: no outcome_hint transitions in any run.

**Fix:** Either make both use raw score, or document this as intentional design (smoothed score is intentionally harder to trigger for outcome_hint).

**Refs:** pacing.md §2.7, §2.9; validation-A-results.md

## 7. HIGH — BREATHER Amplifies Dampening Loop ✅ VALIDATED

**Severity:** HIGH
**Effort:** Medium (config change)
**Files:** `ccya/engine/_pacing.py`

**What:** BREATHER resets convergence to 0-1 and threads lose urgency (sanitizer downgrades during the 1-2 turn BREATHER). After breather exits, convergence must rebuild from scratch.

## 8. HIGH — Curtain Call vs. Extension Conflict ✅ VALIDATED

**Severity:** HIGH
**Effort:** Small (prompt change)
**Files:** `ccya/prompts/narrate_system.j2`

**What:** Curtain call enters "forced" tier at `climax_turn_count >= limit-1` (T3 of CLIMAX), telling the Narrator "MUST resolve" threads. Extension evaluation happens at `climax_turn_count >= limit` (T4).

- At T4: Extension requires sustained urgency (convergence >= 3 AND urgent thread)

**Self-fulfilling prophecy:** Record prompt mandates "at least one thread MUST be urgent in CLIMAX" → Sanitizer downgrades that urgent thread → Convergence drops → Extension fails → CLIMAX ends quickly.

**Impact:** Only 2 of 5 runs extended CLIMAX past limit=4. Extensions are rare because the system actively undermines the conditions needed for them.

Total: 3/5 runs extended. The sanitizer downgrades urgent threads during CLIMAX, causing convergence to drop below 3 by T4. The self-fulfilling prophecy is confirmed: Record mandates urgency in CLIMAX → Sanitizer downgrades → Extension fails.

**Fix suggestions:**
1. Delay curtain_call forced tier to T4+
2. Modify curtain_call guidance during extension-eligible CLIMAX phases
3. Reduce sanitizer dampening during CLIMAX

## 9. HIGH — Thread One-Directionality (Advancement Only) ✅ VALIDATED

**Severity:** HIGH
**Effort:** Small (prompt change)
**Files:** `ccya/prompts/record_system.j2`

**Impact:** Thread urgency/progress state drifts upward. Threads appear to be progressing even when the player is failing. The sanitizer receives these updates but has no downward correction signal.

**Additional context from validation:** noir-1930s has 1 setback in both the 15t (7.1%) and 25t (4.3%) runs — not 0% as previously claimed, but still very low. golden-piracy 25t has 0% setbacks (confirmed). Allied-ww2 has the highest setback rate at 22.2%. Advancement dominance is 78-100% across all runs, confirming the one-directionality finding.

**Fix:** Strengthen the record prompt to require `setback` on fail/setback rolls. Make it a binding instruction, not a suggestion.

## Cross-Cutting Concerns

**1. Convergence formula vs. thread lifecycle contradiction.** The formula weights urgent threads heavily (0-2 points), but the lifecycle (Record + Sanitizer) systematically removes urgency. Either make the sanitizer escalate as well as downgrade, or reduce the weight of urgent_thread in convergence.

**2. Beat system is the de facto convergence driver.** beat_streak contributes 1 on most turns while urgent_thread contributes 0. This inverts the design intent where thread urgency should be the primary pacing signal.

**3. Narrative-mechanical decoupling.** Compendium captures rich NPC characterization (motivation, fear, leverage, tie) but it's not used by the urgency system. Beats are generated but ignored by narration. Threads track narrative tensions independently of NPC presence.

**4. Record extractor is the single point of failure for thread state.** It creates threads, updates urgency, tracks progress, and decides setbacks — all LLM-driven with minimal gating. Implicit thread creation bypasses all safety valves.

**5. Prompt context fidelity vs. state fidelity.** Token truncation affects prompts but not state (state.yaml is always complete). The condition TTL bug affects state directly (not just prompts). These are different failure modes with different impacts.
