PRIORITIZE BY SEVERITY AND IMPACT. Mechanical issues in the engine itself (key mechanics broken, not just prompts) are the TOP PRIORITY. Prompt issues are secondary. Auto-checker failures are background context.

A mechanical issue is one where the ENGINE CODE or DATA FLOW is broken — not just a prompt that could be tightened. Examples:
- Momentum deadlocks (engine fails to generate recovery deltas)
- Conditions not feeding into rules/narration (data flow gap)
- Rules outcome not fed to Narrate (data flow gap)
- Compaction fails to add bullets/sanitize (engine logic gap)
- Beat directive overrides player input (engine priority logic broken)

A prompt issue is one where the engine code is correct but the prompt could be clearer. Examples:
- Missing BINDING marker in narrate prompt
- Quest dedup rules not explicit enough
- NPC exit handling ambiguous in scene prompt

Engine issues go first. Prompt issues go second. Harness/trace changes go third.

---

PROPOSE ENGINE FIXES WHEN THE EVIDENCE WARRANTS THEM. The report may classify an issue as "bad prompt" when the actual root cause is broken engine code. You must independently assess:
- If the judge verdict shows a key mechanic is broken (momentum deadlocks, conditions not feeding rules, rules outcome not reaching Narrate, beat directive overriding player input), propose an ENGINE FIX even if the report says "bad prompt."
- If the engine code has a data flow gap (e.g., `pc.conditions` is never passed to the rules pipeline, `rules_outcome` is never injected into the Narrate prompt), propose a Python fix in the engine code.
- If the compaction logic has a bug (e.g., sanitization checklist is generated but never applied to the JSON output), propose a Python fix in `compactor.py`.
- Do NOT assume "bad prompt" is the root cause. Read the engine code. If the code is correct and the LLM just doesn't comply, then it's a prompt fix. If the code is wrong or missing, it's an engine fix.
- Engine fixes should include full function signatures, the exact code change, and why it fixes the issue. No pseudocode.
