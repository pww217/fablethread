# Roadmap Directory — Frontmatter Schema

All files in `roadmap/bugs/` and `roadmap/features/` **must** have YAML frontmatter. Files without frontmatter are skipped by `scripts/generate-roadmap.py` (warns to stderr).

## Required Fields

Full frontmatter schema with field descriptions: `roadmap/templates/<type>.md` (bug, feature, improvement, or eval).

Required fields: `title`, `status`, `urgency`, `size`, `created`, `ticket_id`.
Optional fields: `design`, `plan`, `pr` (with `url` and `branch`), `labels`.

## Status Lifecycles

### Bugs
- `new` → `validated` → `up-next` → `testing` → `done` or `canceled`
- `canceled` at any point

### Features
- `idea` → `scoping` → `up-next` → `done` or `canceled`
- `canceled` at any point

### Improvements
- `idea` → `scoping` → `up-next` → `done` or `canceled`
- `canceled` at any point

### Evals
- `new` → `triaged` → `up-next` → `done` or `canceled`
- `canceled` at any point

## Workflow Stages

The roadmap is split into three TOC files generated by `make roadmap`:

| File | Statuses | Purpose |
|------|----------|---------|
| `roadmap/backlog.md` | `idea`, `scoping`, `new`, `validated`, `triaged` | What's queued for consideration or awaiting evaluation |
| `roadmap/active.md` | `up-next`, `testing` | Ready to start or being tested |
| `roadmap/done.md` | `done`, `canceled` | What's finished or killed |
| `roadmap/archive.md` | Items in `archive/` | Historical record |

## Categories

| Directory | Purpose |
|-----------|---------|
| `roadmap/bugs/` | Something is broken (expected behavior ≠ actual behavior) |
| `roadmap/features/` | New capability that didn't exist before |
| `roadmap/improvements/` | Existing thing works but could be better (refinement, optimization, QoL) |
| `roadmap/evals/` | Eval findings — hybrid of bug/improvement, not clearly broken but not quite right |

## Auto-Archive

Items with `status: done` or `status: canceled` where `created` > 10 days ago are automatically moved to `roadmap/archive/` when `make roadmap` runs. This keeps `done.md` current without manual cleanup.

Run `make roadmap --dry-run` to preview what would be archived without moving files.

## Conventions

- **One file per bug/feature** — slug = filename without `.md`
- **Status in frontmatter, not directory** — files stay in `bugs/` or `features/` regardless of status; completed items move to `archive/`
- **Labels** — lowercase, kebab-case; used for filtering/grouping in TOC
- **Urgency** — 1=urgent, 2=high, 3=medium, 4=low
- **Size** — small, medium, large, xlarge
- **Ticket ID** — unique identifier: `F-N` (features), `B-N` (bugs), `I-N` (improvements), `E-N` (evals); separate sequences per type
- **Related items** — link via markdown in body: `[Title](../features/other-slug.md)`
- **Cross-linking** — use `design`, `plan`, `pr` frontmatter fields to link lifecycle artifacts

## Ticket Skill

The `ticket` skill (`.opencode/skills/ticket/SKILL.md`) enforces:
- Frontmatter schema compliance
- Status transition validation against lifecycle rules
- Slug naming conventions (kebab-case, descriptive)
- Type inference when ambiguous
- Cross-link field updates (`design`, `plan`, `pr`)

All skills that touch roadmap items should call the ticket skill.

## Generation

Run `make roadmap` to regenerate `roadmap/backlog.md`, `roadmap/active.md`, `roadmap/done.md`, and `roadmap/archive.md` from frontmatter.

## Design Docs

Design docs in `docs/design/` use a separate lifecycle:
- `scoping` → `reviewed` → `implemented`
