## Problem

Beats generated by the world model are too long and prescriptive — they read as full prose scene descriptions rather than structural guidance for the narrator. This:

1. **Constrains the narrator** — the narrator must interpret long prose beats as "creative guidance" while also fulfilling player intent, creating tension between the two.
2. **Ignores NPC agency** — beats are mostly thread-pressure or environmental, with `npcs` almost always empty. The world model has NPC data but doesn't use it.
3. **Redundant with narration** — beats like `[thread_pressure: faction_patrols] "The heavy thud of boots accelerates into a coordinated tactical advance through the thistle fields"` are just prose the narrator will write anyway.
4. **`npcs` field is dropped in ruling phase** — `ruling.py:212` constructs `pending_gm_beat` as `{"type": ..., "effect": ...}` and discards `npcs`. The narrator never sees which NPCs to feature.
5. **Thread repetition** — 12 of 14 beats in the zombie save are `[thread_pressure: faction_patrols]` repeated across 5+ turns. The 5-turn beat history anti-repetition rule doesn't catch this because each beat's `effect` prose is different.

Evidence from `saves/cordyceps-year-twenty-2026-07-05/` (zombie save): all 14 beats have `npcs: []`. 12 of 14 are `[thread_pressure: faction_patrols]` — repetitive, NPC-free, prose-heavy.

## Decisions

### 1. Beat format: recipe, not prose

`effect` becomes a compact directive with bracket tags — not a prose scene description.

Current:
```json
{"type": "pressure", "effect": "[thread_pressure: faction_patrols] The heavy thud of boots accelerates...", "npcs": []}
```

New:
```json
{"type": "pressure", "effect": "[npcs: petty] [highlight: fear] [thread: faction_patrols]", "npcs": ["petty"]}
```

Allowed tags (loose, not strictly enforced):
- `[npcs: name1, name2]` — which NPCs to feature
- `[highlight: motivation|fear|leverage|tie]` — which psychological field to exercise
- `[thread: thread_id]` — which thread to pressure
- `[blend: field1 vs field2]` — cross-NPC collision pattern

The world model can compose any combination of tags. Examples in prompt, not enforced by model schema.

### 2. World model priority order (same level, then fallback)

**Primary (equal priority):**
- NPC + NPC (cross-NPC blending: motivation vs fear, leverage vs tie, etc.)
- NPC + thread (one NPC's psychological field + an active thread)

**Fallback:**
- Single NPC acting on one of their psychological fields
- Thread + thread (valid but rare — threads should intersect organically via the narrator)

**Absolute last resort:**
- Environmental — only when there are literally no NPCs in the scene and no relevant threads

### 3. NPC-only beats rule

The world model may only touch threads **in combination with an NPC**. No single-thread-only or thread+thread beats unless there are no NPCs with real psychological fields in the scene.

- "Real fields" means fields from the NPC roster (motivation, fear, leverage, tie), not fields the model invents.
- Unnamed NPCs with only `bio` + `motivation` count.
- If there are NPCs but none have any psychological fields to work with, threads are allowed.

This is the compromise: the world model still uses threads for pressure, but only when tied to an NPC's agency.

### 4. Anti-repetition: 5-turn thread ban

Explicit ban on re-raising the same thread within a 5-turn window. Not just "avoid repetition" — hard rule. This addresses the feedback loop where `faction_patrols` gets pressed 5+ turns in a row with slightly different prose.

### 5. `npcs` field: formalize on GMBeat model

Make `npcs` a required field on the `GMBeat` Pydantic model. Currently `world.py:188` adds it as a dict spread after validation. Making it part of the model schema means the LLM sees it as part of the output contract.

### 6. `npcs` must flow through ruling to narrator

Currently `ruling.py:212` drops `npcs` when constructing `pending_gm_beat`. Must pass it through so the narrator can see which NPCs to feature.

### 7. NPC scope for world model: keep as-is (present only)

Do NOT expand to nearby/known NPCs. The re-injection loop problem is real — when `nearby` NPCs were included, the world model would constantly re-add NPCs the player had just escaped.

### 8. Beat type semantics: no type biases toward threads

Threads are last resort for ALL beat types, not just some. The world model should favor NPC-driven beats equally regardless of type.

No type-specific templates or biased examples in the world prompt. The beat types carry semantic meaning for the *narrator* (type `pressure` = something's pushing forward, type `complication` = something makes things harder, type `revelation` = new information), but these don't bias the world model toward any particular directive style.

The world model composes freely using the NPC-first priority order, regardless of which type it picks.

### 9. Beat types: 8 types, drop hazard

Dropped: `hazard` — essentially never chosen, purely environmental, no NPC agency.

**Remaining 8 types:**

**Tension bucket** (pressure, complication, escalation, setback):
- `pressure` — existing thread advances / something pushes forward
- `complication` — completely new element enters the scene
- `escalation` — existing threat intensifies
- `setback` — PC loses ground

**Discovery bucket** (revelation, twist, callback):
- `revelation` — new information appears
- `twist` — unexpected turn / role reversal
- `callback` — reference to past events resurfaces

**Respite bucket** (opportunity, breathing_room):
- `opportunity` — beneficial opening appears
- `breathing_room` — moment of respite

**Bucket rename:** pressure/situation/relief → tension/discovery/respite. The buckets only affect convergence scoring (tension beats count toward CLIMAX pressure streak). They have no other computational effect.

`setback` stays in the tension bucket — it represents the PC losing ground, which is tension, not a new element.

### 10. Narrator interpretation: update instructions, not new fields

The narrator already receives `type` and `effect`. Just update the narrator prompt to explain how to parse recipe-format brackets. No new fields needed beyond `npcs`.

Current rendering in `narrate_user.j2:91-93`:
```
**Beat:** PRESSURE — [thread_pressure: faction_patrols] The boots get louder. Use this as creative guidance.
```

New rendering:
```
**Beat:** PRESSURE — [npcs: petty] [highlight: fear] [thread: faction_patrols]
```

The narrator prompt gets a short section explaining bracket syntax. The narrator infers from context what to do — no prose translation.
